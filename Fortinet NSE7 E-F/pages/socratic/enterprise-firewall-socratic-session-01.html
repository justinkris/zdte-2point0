OVERVIEW

Why perimeter-only security is no longer enough

Traditional security drew a wall around the network and trusted everything inside. This worked when users sat at fixed desks, apps ran in the datacentre, and threats came exclusively from outside. None of those conditions hold today.

Core idea: Perimeter security grants implicit trust based on location. Zero trust replaces this with identity and context-based continuous verification — trust is never assumed, always earned.

How the perimeter became irrelevant

Attackers no longer need to punch through the firewall. Three vectors bypass it entirely without triggering any alert:

  • Dormant malware — implanted on a user device, activates only once the device connects to the corporate network
  • Credential theft via phishing — attacker authenticates as a legitimate user; the firewall sees a valid login and waves them through
  • Exposed application exploitation — if a port is permitted, the firewall allowed it; any vulnerable app behind that port is reachable
★
EXAM NOTE
In all three bypass vectors the perimeter firewall sees nothing suspicious. The wall didn't fail — it became irrelevant. This is the foundational argument for zero trust architecture.

The zero-trust response

If location cannot be trusted, access decisions must be based on something richer. Zero trust evaluates multiple factors on every request — not just at login.

Trust Factor What it checks Replaces
IdentityAuthenticated user, not just source IPIP address = trusted
Device postureIs the device compliant, patched, managed?Corporate device = trusted
Location contextWhere is the connection originating from?Inside network = trusted
ApplicationWhat specific resource is being accessed?Port-based allow/deny
BehaviourIs this access pattern normal for this user?No ongoing check
Continuous validationTrust re-evaluated throughout session, not just at loginSession-based trust after auth

ANALOGY
Perimeter security is a castle with a moat — cross the drawbridge and you roam freely. Zero trust is a government building — you show ID at reception, badge in at every door, and each room checks whether you belong there.
NGFW & FORTIGUARD · WHAT NEXT-GEN ACTUALLY MEANS

NGFW vs traditional firewall

A traditional firewall makes decisions at Layer 3–4: source IP, destination IP, port, and protocol. An NGFW extends inspection to Layer 7 — it sees into the application itself, regardless of which port it uses.

The port-hiding problem: Any application can run over any port. Port 443 can carry malware C2 traffic, data exfiltration, or anything else. A firewall that allows port 443 and assumes the content is safe is blind to what is actually inside the stream.

FortiGuard Labs vs FortiGuard subscriptions

These two terms are often confused. They refer to different things and the distinction is exam-relevant.

FortiGuard Labs
Fortinet's internal threat research organisation. They hunt malware, reverse-engineer exploits, discover vulnerabilities, and build the signature databases. They are the source of intelligence — not a product you subscribe to.
FortiGuard Subscriptions (Services)
The licensed delivery mechanism that pushes FortiGuard Labs intelligence to your FortiGate. Each service (IPS, AV, Web Filter, App Control, DNS Filter) is a separate subscription. Without a valid licence, updates stop — the FortiGate keeps running on stale data.

What each FortiGuard service delivers

Signatures for known exploit patterns and attack techniques
AV

Layer 7 application identification database

Web Filter
URL categorisation and reputation database
!
COMMON MISTAKE
An expired FortiGuard licence does not disable the FortiGate. The device keeps forwarding and enforcing existing rules — it just stops receiving fresh signature updates. Databases go stale. New threats become invisible. Do not confuse "subscription expired" with "firewall broken."
TRAFFIC & DEPLOYMENT · WHERE INSPECTION HAPPENS

North-south vs east-west traffic

Where a firewall sits determines what traffic it can see. The two fundamental flow directions in enterprise networks require different placement strategies and different FortiGate deployment families.

Direction Definition Perimeter FW sees it? Enforcement point
North-SouthTraffic crossing a network perimeter — internet to internal, branch to DC, remote user to HQYes — this is its purposeDCFW / DEFW at the edge
East-WestTraffic between internal hosts, segments, VMs, or workloads within the same networkNo — never traverses the perimeterISFW inline between segments
Why this matters: An attacker who lands inside the network via phishing operates entirely in east-west space. Without an ISFW, they traverse segments freely — the perimeter firewall never sees the lateral movement.
Internet → Perimeter FW [N-S] → Corp Network ⇄ ISFW [E-W] ⇄ Internal Segments

Fortinet deployment families

Fortinet names four deployment models, each solving a specific placement problem. Scenario questions will test whether you can match a business requirement to the right family.

DC
DCFW — Data Centre Firewall — High-throughput enforcement at the datacentre edge. Handles both north-south ingress/egress and east-west between DC segments. Built for maximum performance.
IS
ISFW — Internal Segmentation Firewall — Sits inline between internal network segments. Enforces east-west policy. Prevents lateral movement by requiring all cross-segment traffic to pass inspection.
DE
DEFW — Distributed Enterprise Firewall — Lightweight FortiGate deployed at branch offices. Brings consistent security enforcement to many distributed locations without large appliances at each site.
☁
Cloud variants — FortiGate-VM / CNF / FortiSASE — FortiGate-VM deploys inside AWS, Azure, or GCP as a virtual machine. CNF (Cloud-Native Firewall) is a managed service for containerised and Kubernetes workloads. FortiSASE enforces policy at the cloud edge — policy follows the user, eliminating backhaul for remote access to SaaS apps.
→
TIP
FortiSASE solves the backhaul problem: a remote user in Sydney accessing Microsoft 365 (also in Sydney) should not have their traffic hauled to the Melbourne DC and back out again. SASE enforces at the nearest PoP — latency drops, experience improves, policy still applies fully.
SCENARIO — EXAM QUESTION STYLE
A company has 200 branch offices globally. Each site needs local security enforcement without deploying high-end appliances. Users at each branch access both local resources and the internet directly. Which Fortinet deployment family is the best fit?
Answer: DEFW — Distributed Enterprise Firewall. Designed for lightweight, consistent enforcement at many distributed branch locations. DCFW is over-engineered for a branch. ISFW addresses internal segmentation, not branch edge enforcement.
EXAM TIPS

What the exam focuses on

Session 01 concepts appear most often in scenario-style questions testing whether you can map a business requirement to the correct architecture decision. Focus on the reasoning, not just the names.

!
TRAP — PORT ≠ APPLICATION
Port 443 does not guarantee HTTPS, and HTTPS does not guarantee safe content. Any application can tunnel over 443. A policy that permits 443 without Layer 7 inspection is blind to what is inside. NGFW App Control solves this — traditional firewall does not.
!
TRAP — LABS ≠ SUBSCRIPTION
FortiGuard Labs is Fortinet's threat research organisation — the team that builds intelligence. A FortiGuard subscription is the licensed service that delivers that intelligence to your FortiGate. They are not the same thing. Exam questions may use both terms in close proximity to test this distinction.
!
TRAP — EXPIRED LICENCE ≠ BROKEN FIREWALL
An expired FortiGuard subscription does not disable the FortiGate. It continues to enforce existing policies and forward traffic. What stops is signature database updates. The device goes blind to new threats gradually — it does not stop functioning.
!
TRAP — DEFW vs ISFW
DEFW = distributed branches, many locations, lightweight edge enforcement. ISFW = internal segmentation, east-west inspection between segments inside a network. A scenario describing branch offices points to DEFW. A scenario describing lateral movement prevention inside a datacentre points to ISFW.
