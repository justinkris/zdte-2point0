Minor — Terminology: Retrieve vs Import
Used the word "import" when describing the action of pulling a live FortiGate config into FortiManager.
▸ Correct Terminology
The correct FortiManager term is Retrieve — not import. The exam expects this specific word. Low priority but noted — one mark is still one mark.
!
Medium — Install Workflow: Install vs Reinstall Policy
Confused by first-time vs repeat framing. Framed the distinction as "new vs existing" rather than the actual mechanical difference between the two operations.
▸ Correct Understanding
Install Policy Package = full wizard — select the package, select the target devices, step through the preview. Used when you need to choose or confirm scope.
Reinstall Policy = skips the wizard entirely and goes straight to the preview using the same package and devices as last time. The key signal: wizard steps vs bypass.
!
Medium — Script Type Selection: CLI vs Tcl
Selected CLI for a conditional logic scenario in Session 03. Missed the if/then/else signal that forces the type choice. Session 04: correct instinct on Tasks A and B — instinct is locking in.
▸ Correct Understanding
Tcl = any scenario with if/then/else, loops, or decision logic. If the requirement has conditions, the answer is always Tcl.
CLI = flat command list only — no branching, no logic, just sequential commands. No logic needed = no Tcl.
!
Medium — Jinja2 Scope
Applied Jinja2 to a policy package script scenario. Jinja2 lives inside CLI Templates in the device layer — it is a templating language, not a script runner. It cannot touch the policy layer.
▸ Correct Understanding
Policy package scripts = CLI or Tcl only. Jinja2 does not appear as an option here.
Jinja2 = device layer only — lives inside CLI Templates and renders $variables into device configuration at install time. The moment a scenario mentions the policy layer or policy packages, Jinja2 is out of scope.
