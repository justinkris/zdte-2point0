01
Navigating the ZDX Admin Portal
Dashboards · Applications · Users · Root Cause Analysis · Call Quality · Inventory · Deep Tracing · Alerts
›
LAB OVERVIEW
Familiarise yourself with the ZDX Admin Portal UI — dashboards, reports, and menu functions. Follow the step-by-step tasks or explore on your own. After this lab you will apply your knowledge to real troubleshooting scenarios in Labs 2–11.
OBJECTIVES
  • View ZDX Dashboards (Performance Overview, Incidents, Self Service)
  • View Applications Overview and User Overview dashboards
  • Use the ZDX Y-Engine for Automated Root Cause Analysis
  • View Microsoft Teams Call Quality dashboards
  • Browse Software and Device Inventory reports
  • View Deep Tracing results and active Alerts
1.1
View ZDX Dashboard
›
  1. Launch the ZDX Admin Portal — open https://admin.zdxcloud.net/ in your browser:
    • Admin User ID: <ZDX Admin User ID>
    • Session Password: <Session Password>
    • Click Sign In
  2. Explore the Performance Overview widgets:
    • At the top, select 24 Hours from the dropdown
    • Scroll through the Most Impacted Applications list and click any app to update the map view
    • Use + / – controls to zoom the map (or Ctrl + mouse wheel)
    • Click Draw Fence → draw a rectangle around a geographic area → click Filter Selection
    • Click any point in a graph for more details
    • Click Add Another Application and select one from the dropdown
    • Click Reset on the map, then try the Geolocations filter at the top → Apply → view reports → Reset
  3. Explore Incidents Overview:
    • Navigate to Dashboard > Incidents Overview
    • Scroll to the Incidents by Epicenters map, click a marker and select an incident
    • Click View Incident Details and review the metrics
  4. Explore Self Service Overview:
    • Navigate to Dashboard > Self Service Overview
    • Review summary graphs for notifications in the selected timeframe
    • Click to see details for a specific notification
1.2
View Applications Overview Dashboard
›
  1. From the main menu, select Applications
  2. Sort the applications table by ZDX Score Trend
  3. Click the application with the lowest ZDX Score
  4. In the ZDX Score Over Time graph, drag to zoom in on a period with significant change → click Zoom out
  5. Scroll down to view Page Fetch Time graph and most impacted Departments, Regions, and Zscaler Locations
  6. View information about the application's configured probes
1.3
View User Overview Dashboard
›
  1. From the main menu, select Users → select an application from the dropdown → click Apply
  2. Under ZDX Score User Distribution, toggle between Poor / Okay / Good to update the user table
  3. Select a user with Poor or Okay performance → review device info (OS, IP)
  4. Click View More Device Details → explore Hardware, Network, and Software tabs → Done
  5. Review Web Probe Metrics:
    • Scroll to Web Probe Metrics graphs
    • Click on a graph spike to see details (Page Fetch Time, Server Response Time, etc.)
  6. Review Cloud Path Probe Metrics:
    • View the Cloud Path graph for Latency and Packet Loss
    • Scroll to the Hop View → expand the leg with the highest differential latency (shown in orange)
    • Mouse-over hops for details; click Command Line View to identify high-loss hops
  7. Review Device Health:
    • Customise the graphs (e.g. unselect Disk)
    • Click a graph point for CPU Usage details and Most Impacted Processes
    • Under User Device Events, mouse-over a timeline dot to view event details
1.4
View Automated Root Cause Analysis
›
  1. From the main menu, select Search → type Curtis Hardwick → press Enter → click the user name → select an application → Apply
  2. In the ZDX Score Over Time graph, click a point with a Poor score → click Analyze Score → review the root cause analysis table
  3. Scroll through Web Probe Metrics, Cloud Path view, and Device Health to confirm the analysis
  4. Drag the slider to select a time range → click Analyze Range → review results → provide feedback using the buttons
  5. Click Compare to → select Same time 1 day ago → scroll through side-by-side comparison graphs and identify key differences

View Call Quality Dashboards

  5. Scroll down to Meeting Monitoring Metrics → click a graph point for details

View Inventory Dashboards
›

View Deep Tracing Results

Familiarity with the ZDX portal layout is the prerequisite for every troubleshooting workflow — engineers who know where dashboards, RCA, deep traces, and alerts live can navigate to the right data in seconds rather than minutes during an active incident. In digital experience monitoring, time to data directly equals time to resolution.

A user reports frequent disconnections, slow internet speeds, and difficulty completing work tasks. Initial indications point to poor WiFi but details are vague. Use ZDX to pinpoint the exact root cause.
User: Curtis Hardwick Device: PC-Curtis-WiFi Timeframe: Last 48 Hours
OBJECTIVES
  • Filter ZDX Score and application data for the user over the incident period
  • Use the Y-Engine Analyze Score to identify impacting factors
  • Compare Cloud Path data before and after ZDX score degradation
  • View Device Events associated with ZDX score changes

2.1
View User ZDX Score for an Application
›
  1. Click User Search → type Curtis Hardwick → click the user name in results
  2. Select time period: 48 Hours
  3. Select an application (e.g. Salesforce Lightning)
  4. View the ZDX Score Over Time graph — observe that the score fluctuates frequently between Good and Poor
2.2
Analyze Poor ZDX Score Interval
›
Zoom in on a Poor score period and use the Y-Engine to identify likely contributing factors. Results vary — explore different data points.
  1. In the ZDX Score Over Time graph, click and drag to zoom in on a period where the score is Poor (ensure the selection includes time before and after the drop)
  2. Click on a point with a Poor score → click Analyze Score (takes a few seconds)
  3. Review the results table: "The following factors might have impacted the ZDX score"
    • In this example: Low Wifi Signal + Suboptimal Wifi after connecting to 3Com_Wifi SSID
★
NOTE
Traffic is simulated — your results will differ from examples. Repeat against different data points to explore varying conditions.
2.3
Compare Poor Score to Last Known Good
›
  1. Click Compare to for the selected point → select Last known good score
  2. Examine the key differences, particularly:
    • ZDX Score value
    • WiFi identifier (SSID change: Google_Nest → 3Com_Wifi)
    • Client-Egress Latency
2.4
Isolate High Latency Hop
›
  1. Click ← Compare ZDX Scores to return to the user report
  2. Zoom in again on a Poor ZDX Score period
  3. Scroll down to the Cloud Path graph — note the shift from low to high latency when the score drops to Poor
  4. Examine the Hop View below the graph — it shows each detected hop and its latency
    • Example: the first hop (device → local gateway) accounts for 319ms of 339ms total — that is the bottleneck
    • If data is missing (network was lost), pick a different time point where data appears in the graph
2.5
View User Device Events Associated with Score Changes
›
  1. Scroll to the bottom of the page to view the User Device Events timeline
  2. Mouse-over the dot on the Network timeline at the time the ZDX Score dropped to Poor — view the Network Interface pop-up
  3. Scroll through the data to identify what changed (look for a value in the New Value field)
    • Example: SSID change from Google_Nest to 3Com_Wifi
  4. Mouse-over the dot when the score returned to Good — confirm the SSID switched back to Google_Nest
WHY THIS MATTERS

WiFi issues account for a disproportionate share of user experience complaints, yet traditional IT monitoring tools only see layer-3 and above — they cannot detect SSID roaming, signal degradation, or channel congestion. ZDX correlates WiFi metrics with ZDX Score drops so engineers can present the evidence to end users and network teams rather than falling back on "works on my machine."

Confirm Sporadic SaaS Application Performance

›
  1. Scroll to Web Probe Metrics → analyze the Page Fetch Time graph for patterns
  2. Observe: PFT is below baseline (green line) for periods, then suddenly spikes — corresponding to Poor ZDX Score drops

›

  2. Examine the latency metrics for each path segment:
    • Example: Client-Egress contributes 496ms of the overall 551ms end-end latency
5.4
Analyze High Hop Latency
›
  1. Scroll to the Hop View → locate the high-latency link (example: Client-Egress at 496ms)
  2. Click the magnifying glass icon to expand the hop details
    • Example: high latency isolated between Client Gateway 10.1.2.1 and next hop router 10.0.0.254
5.5
Confirm Key Differences with ZDX Score Comparison
›

  3. Click View Detailed Cloud Path for a direct Hop View comparison → Close
  4. Click ← Compare ZDX Scores to return
WHY THIS MATTERS

Network router and hop-level latency is one of the leading causes of application slowness that neither the application team nor the end user can explain — it lives in the middle-mile between the device and the cloud. ZDX's hop-by-hop visibility gives engineers the specific router IP and latency delta needed to open a ticket with an ISP or internal network team backed by objective data rather than user anecdote.

Data Explorer allows you to create and customise views of applications and metrics — comparing performance across multiple apps and geolocations in a single interface. A powerful tool for identifying trends and correlating data across your organisation.
