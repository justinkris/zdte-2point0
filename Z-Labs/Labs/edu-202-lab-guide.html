Connectivity Services — Browser Access for 3rd Parties (HVAC)
⏱ 75 minutes · App Connector · BA Cert · App Segment · DNS CNAME
›
SCENARIO
Safemarch outsources HVAC monitoring. The 3rd party authenticates via SAML but has no Client Connector — provide them browser-only access to the internal HVAC console via ZPA Browser Access. Stages: provision App Connector → create signed Web Server cert → create App Segment + Access Policy → create public DNS CNAME → test from remote network.
OBJECTIVES
  • Provision and activate the Corp: ZPA Connector
  • Create CSR, sign with PATraining CA, upload signed cert to ZPA
  • Create the HVAC Application Segment with Browser Access enabled
  • Create the public DNS CNAME for the BA exporter
  • Test browser access from the Remote: Linux Client PC
3.1
Provision App Connector (OnPrem)
›
  1. On Corp: Win Svr, login as Administrator/Admin-123!. Open the ZIdentity landing page → ZPA tile.
  2. Locate the provisioning key:
    • Configuration & Control > Private Infrastructure > App Connector Provisioning Keys
    • Select OnPrem provision key → click Copy icon
    • Paste into Notepad → Save to Desktop with filename "provision_key" (quotes prevent .txt being added)
  3. On Corp: ZPA Connector (login admin/zscaler), start SSH: sudo systemctl start sshd sudo systemctl status sshd Confirm active (running).
  4. On Corp: Win Svr, open WinSCP → Corp: ZPA Connector saved session:
    • Protocol: SFTP  ·  Host: 10.0.0.3  ·  Port: 22
    • Username: admin  ·  Password: zscaler
    • Click Update if a cert warning appears (expected)
    • Right-click provision_key → Upload to /home/admin
  5. Back on the ZPA Connector, move the key into place: sudo systemctl stop zpa-connector cd /home/admin ls sudo cp provision_key /opt/zscaler/var/ sudo ls /opt/zscaler/var/
    !
    FILENAME GOTCHA
    File MUST be named exactly provision_key — NOT provision_key.txt or provisioning_key. Case-sensitive.
  6. Activate & enable on boot: sudo systemctl start zpa-connector sudo systemctl enable zpa-connector sudo systemctl status zpa-connector Wait ~10s, confirm active.
  7. In ZPA Portal: Configuration & Control > Private Infrastructure > App Connectors — confirm the connector is listed and Connected.
3.2
Create HVAC Web Server Certificate (CSR + Signed Cert)
›
In production, public CAs sign these. For the lab, the PATraining enterprise CA on Corp: Win Svr signs the CSR.
  1. On Corp: Win Svr, ZPA Portal → Configuration & Control > Certificate Management > Certificates → Create CSR.
  2. Populate the CSR fields:
    • Name: HVAC
    • Description: HVAC Server Certificate
    • Subject: CN=<Student ID>.hvac.safemarch.com,O=safemarch,ST=NY,C=US,L=NY,OU=hvac
    • Subject Alternate Name: <Student ID>.hvac.safemarch.com
  3. Click Create.
    →
    CN vs SAN
    Normally CN must match the external FQDN. If external differs from internal, set the SAN to the internal FQDN to avoid mismatch warnings.
  4. Download the CSR:
    • Click Download .CSR File → save as HVAC.csr in \Downloads
    • Open in Notepad → Select All → Copy
  5. Sign the CSR with the PATraining CA:
    • Open the Microsoft Cert Services page (provided in lab) → sign in
    • Submit the CSR → choose Web Server template → submit
  6. Download the signed cert:
    • Certificate Issued → select Base 64 encoded
    • Click Download certificate → save (default certnew.cer)
  7. Upload to ZPA:
    • Return to Configuration & Control > Certificate Management > Certificates
    • Click Upload Certificate next to your CSR → Select File → choose the .cer → Upload
    • Confirm Expiry Date is populated and Upload action is gone

07
Cyberthreat Protection — Sandbox File Inspection
⏱ 15 minutes · Catch-all Sandbox Rule · Quarantine
›
SCENARIO
Configure a catch-all Sandbox rule to inline-quarantine first-time downloads of all file types and block subsequent downloads.
7.1
Configure Sandbox Policies (Catch-all)
›
  1. ZIA Admin Portal → Policy > Sandbox → Add Sandbox Rule.
  2. Configure:
    • Rule Name: Catch-all
    • CRITERIA — File Types: select ALL groups (Archive, Executable, Microsoft Office, Mobile, Other Documents, Web Content)
    • Sandbox Categories: select all from drop-down
    • Protocol: select all
    • ZPA Application Segment: Inspect App Segments
  3. ACTION:
    • First-Time Action: Quarantine
    • Action for Subsequent Downloads: Block
  4. Save + Activate.
→
QUARANTINE vs BLOCK
First-time Quarantine holds the file inline while Sandbox analyzes. Subsequent matches are Blocked outright since verdict is now known. This combo balances user experience (don't block known-good repeatedly) and safety (don't let unknowns through).
WHY THIS MATTERS

Cloud sandbox fills the gap between signature-based AV (which only catches known threats) and allowing all downloads unchecked. The quarantine-then-block pattern prevents productivity loss on benign first-time files while ensuring that a malicious file's verdict is shared globally — once one user is protected, every user on the platform is protected from that file automatically.

Build Isolation Profile (Render Only)
›
  1. ZIA Admin Portal → Administration > Browser Isolation → Add Profile.
  2. General:
    • Name: Render Only
    • Description: Render docs in Isolation, but not allow download, upload, copy, or paste.
    • Click Next
  3. Company Settings → ROOT CERTIFICATES (.pem): Zscaler Root Certificate.
  4. Security → scroll to View office files in isolation: Enable.
  5. Regions → Isolation Regions: Any.
  6. Click Save.
8.2
Implement Isolation Policy (URL Filtering)
›
  1. Policy > URL & Cloud App Control → URL Filtering Policy tab → Add URL Filtering Rule.
  2. Configure rule:
    • Rule Order: 1 · Rule Name: Isolate Test
    • CRITERIA — URL Categories: Social Networking, Social Networking Adult
    • Protocols: HTTP, HTTPS
    • User Agent: Chrome, Firefox, Microsoft Edge, Safari
    • ACTION — Web Traffic: Isolate
    • Isolation Profile: Render Only
  3. Save + Activate.
8.3
Add URL/Cloud App Isolate Control Policy (Twitter/Reddit)
›
  1. Policy > URL & Cloud Application Control → Cloud App Control Policy tab → Add → Social Networking.
  2. Configure:
    • Rule Order: 1 · Rule Name: Social_Networking_2
    • Cloud Application: Twitter and Reddit
    • User Agent: as required
    • ACTION — Web Traffic: Isolate · Isolation Profile: Render Only
  3. Activate.
  4. Test: visit reddit.com or twitter.com — should render in isolation.
    !
    RENDER ONLY ERROR?
    If Render Only throws errors, switch to Default Isolation Profile for testing.
WHY THIS MATTERS

Browser isolation is the final layer of the defense-in-depth stack. When a site clears URL filtering but carries inherent risk — social media, consumer apps, uncategorised destinations — isolation ensures that even if malicious content is served, only safe pixels reach the endpoint. No script executes, no file downloads to the device; the threat stays confined to the cloud container.
