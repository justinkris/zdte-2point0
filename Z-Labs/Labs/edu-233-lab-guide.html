Securing Access to Internet
SSL Inspection · ZIA Policies · Zscaler Root CA · Prerequisite for BI
›
OVERVIEW
SSL inspection is a prerequisite for Browser Isolation — without it, HTTPS traffic cannot be redirected to the isolation container. Review the existing SSL policies and verify that Zscaler is decrypting traffic on the Client PC.
OBJECTIVES
  • Understand why SSL Inspection is required before Browser Isolation can function
  • Review existing SSL Inspection policies and exemptions in the ZIA Admin Portal
  • Confirm Zscaler is decrypting HTTPS traffic by inspecting the Zscaler Intermediate Root CA certificate
1.1
Review SSL Inspection Policy & Verify SSL Decryption
›
  1. Open a browser and go to the ZIA Admin Portal: https://admin.zscalerthree.net
    • Admin User ID: <ZIA/ZPA Admin User ID>
    • Session Password: <Session Password>
  2. Navigate to Policy > SSL Inspection — review examples of SSL policies
    • Note default policies: Office 365 One Click and Zscaler Recommended Exemptions
    • Click the icon for any policy to explore its settings
  3. On the Client PC VM, open a browser → go to https://www.microsoft.com
  4. View the certificate (click the lock icon in the address bar → More Information)
    • Confirm the certificate is signed by Zscaler Intermediate Root CA — SSL inspection is active
★
NOTE
Viewing certificates varies by browser. Look for the lock icon → Connection is secure → Certificate details.
WHY THIS MATTERS

SSL inspection is the foundation every Browser Isolation deployment builds on. In production, a missing or misconfigured SSL policy is the single most common reason isolation policies fail to fire — without decryption, Zscaler cannot inspect HTTPS traffic and cannot redirect it to an isolation container.

02
Managing Browser Isolation Basics
Isolation Profiles · Security Controls · Banners · ZIA & ZPA Profiles
›
OVERVIEW
Browser Isolation configuration requires two steps: creating Isolation Profiles (which define how and where a user is isolated — region, security controls, certificates, cookies, PAC files, banners) and creating Policies that reference those profiles.
PROFILE SETTINGS
  • Region: which geographic region serves the isolation container
  • Security Controls: upload/download, clipboard, print, read-only, watermark
  • Root Certificates: which CAs the isolation browser trusts
  • Cookie Persistence: persist across sessions or not
  • PAC File: applied to the isolated browser
  • User Experience: isolation banner displayed, isolation mode (native vs Browser-in-Browser)
2.1
Create Isolation Profiles
›
  1. In the ZIA Admin Portal, navigate to Administration > Browser Isolation → scroll through the list of pre-created isolation profiles
  2. Click the icon for any profile (e.g. TZTE Render Only):
    • Click Next → review Company Settings: PAC file and Root Certificates applied to the isolation browser
    • Click Next → review Security settings and Regions
    • Click Next → review the Isolation Experience page, especially the banner referenced in this profile
    • Click Close
  3. Click the Isolation Banner tab → review the configured banners (referenced in each profile's Isolation Experience section)
→
ZPA PROFILES
ZIA and ZPA Isolation Profiles are mutually exclusive. ZIA profiles can only be used in ZIA policies; ZPA profiles only in ZPA policies. To view ZPA profiles: login to the ZPA Admin Portal → Configuration & Control > Browser Isolation > Isolation Profiles.
WHY THIS MATTERS

Isolation Profiles are the reusable building blocks that let security teams enforce least privilege on web browsing. Rather than a binary allow/block, organisations can craft a profile per use case — full read-only isolation for contractors, clipboard access for power users, print-only for compliance-sensitive content — without creating separate policies for every scenario.

Managing One-Click Smart Browser Isolation
AI/ML Detection · Smart Isolate · Suspicious URLs · Read-Only Mode
›
OVERVIEW
Smart Browser Isolation automatically isolates potentially malicious web content using AI/ML — no manual URL category configuration required. It identifies suspicious sites, decrypts them via SSL inspection, and presents a pixel stream in a remote isolated browser.
OBJECTIVES
  • Review the one-click AI/ML Smart Isolation setting and associated profile in ZIA
  • Access a suspicious test URL and confirm it opens in a read-only isolation session
  • Verify that text input is blocked, confirming the Render Only profile is enforced
3.1
Configure Smart Browser Isolation
›
  1. Navigate to Policy > Secure Browsing > Smart Isolate
  2. Review the Enable AI/ML based Smart Browser Isolation one-click setting
  3. Verify the Isolation Profile selected is TZTE Render Only
    • This profile has Read Only enabled — users cannot type into isolated pages
3.2
Test Smart Browser Isolation
›
  1. On the Client PC VM, go to: https://www.fakebankstatement.co.uk
    • The webpage opens in isolation with a banner: "This page is rendered in read-only isolation mode"
  2. Click the icon in the bottom right corner of the browser window → view the isolation browser's URL bar
  3. Click the button for additional information → confirm the Isolation Profile name in use
  4. Verify Read-Only is enforced:
    • Click ORDER NOW → click Bank Statements Order Form
    • Scroll to the Email field and try to type — no text input is possible
WHY THIS MATTERS

Zero-day phishing sites are registered daily and often appear legitimate for hours before blocklists catch them. Smart Isolation's AI/ML layer gives organisations a proactive defence that doesn't rely on reputation databases — suspicious pages are sandboxed automatically before the user can interact, reducing dwell time and endpoint exposure without any manual policy work.

URL Filtering · Isolate Action · Copy-Print-Watermark Profile · News & Media

The Isolate action in URL Filtering goes beyond Allow/Block — it lets users access sites productively while containing risk in a cloud browser. Configured URL categories are isolated using the selected profile's security controls.
OBJECTIVES
  • Locate URL Filtering policies configured with Isolate as the action
  • Access BBC News in isolation and observe the Copy-Print-Watermark profile in action
  • Verify copy-from-isolation is allowed while paste-into-isolation is blocked
4.1
Configure URL Filtering Policies with Isolate as Action
›
  1. In the ZIA Admin Portal, navigate to Policy > URL & Cloud Application Control > URL Filtering Policy
  2. Review the configured URL filtering policies — look for a policy isolating News, Sports, and Media categories
4.2
Test Isolate as an Action in URL Filtering Policies
›
  1. On the Client PC VM, go to https://www.bbc.com
    • The site loads in isolation using the Copy-Print-Watermark profile
  2. With this profile you can:
    • Copy from isolation to your local computer ✓
    • Print the page ✓
    • See a watermark on the isolated session ✓
    • Copy from local to isolation is disabled ✗
  3. Verify you cannot paste local clipboard text into the isolated page
★

WHY THIS MATTERS

News and media sites carry legitimate content but also serve ads from third-party networks that regularly host drive-by downloads — a common ransomware delivery vector. Isolating these URL categories lets organisations permit access without exposing endpoints to scripts or executables embedded in ad networks, while still allowing users to copy and print content they legitimately need.

06
Inspecting Cloud Browser Isolation Logs
Web Insights · Road Warrior · Cloud Browser · Log Filtering
›
OVERVIEW
Isolation traffic appears in Web Insights under two location categories: Road Warrior (the user's device request) and Cloud Browser (activity inside the isolation container). Together they give the full picture of an isolated session.
OBJECTIVES
  • Filter Web Insights logs by the Road Warrior location to find the initial BBC News request
  • Add the Cloud Browser location filter to see activity logged inside the isolation container
  • Understand how the two log categories combine to represent a complete isolated session
6.1
Review Log Details
›
  1. In the ZIA Admin Portal, navigate to Analytics > Web Insights → click Logs
  2. Set Timeframe to Current Day (or the period when you completed tests)
  3. Click Add Filter → scroll down → select Location → choose Road Warrior → Done
  4. Click Add Filter → type URL Search → change Domain to Host → operator: Contains → type bbc.com
  5. Click Apply Filters → review the log entries
    • You should see bbc.com allowed for isolation with the Copy-Print-Watermark profile
  6. Now add Cloud Browser to the Location filter to see the full picture:
    • Edit the Location filter → also select Cloud Browser → Apply Filters
    • The logs now show: initial request (Road Warrior) → isolation container launched (Cloud Browser) → all activity inside isolation logged
WHY THIS MATTERS

Without dual-location logging, a SOC analyst investigating an incident would only see the initial request — not what happened inside the isolation session. The Road Warrior / Cloud Browser log chain is the evidentiary record proving what was accessed and confirming no data crossed the network boundary, often a mandatory audit trail under PCI-DSS, SOC 2, or GDPR compliance frameworks.

07
Applying Document Isolation Controls
Document Viewing · Protected Storage · Print Only Profile · PDF Rendering
›
OVERVIEW
Browser Isolation can render, transfer, download, view, and print web pages and documents without exposing the organisation to zero-day risk. Files are converted to PDF in the isolation container and held in Protected Storage — a temporary secure area for the duration of the session.
OBJECTIVES
  • Review the Print Only isolation profile and its document security controls
  • Download a DOC file from the internet into Protected Storage within the isolation session
  • Render the document as a flattened PDF and confirm print is allowed while local download is blocked
7.1
Enable Document Viewing and Security Controls for Your Isolation Profile
›
Review the Print Only isolation profile to understand document viewing and security control settings.
  1. Navigate to Administration > Browser Isolation
  2. Click the icon next to the Print Only profile → review the configuration:
    • On the Security tab, scroll down to review text input settings and Office file viewing settings
  3. Confirm this profile's controls:
    • Copy / paste / upload / download: disabled ✗
    • Page is Read-Only, Office file rendering allowed, watermarked
    • Print is allowed ✓
7.2
Test Document Viewing in Isolation
›
  1. On the Client PC VM, go to: https://file-examples.com/index.php/sample-documents-download/sample-doc-download/
  2. Verify the site opens in isolation
  3. Click DOWNLOAD SAMPLE DOC FILE for the 100kB DOC file
    • The file downloads to the Protected Storage of the isolation session
  4. Click the file to render it as a PDF within the isolated session
  5. Check Protected Storage — click the icon in the upper-right corner of the isolation session to see the downloaded file
  6. Try to print the file using the isolation print controls
★
NOTE
Isolation converts multiple document formats (DOC, DOCX, XLSX, PDF, etc.) into PDF for safe viewing inside the container. Protected Storage is purged when the session ends.
WHY THIS MATTERS

Malicious Office documents — macros, embedded OLE objects, polymorphic VBA — remain the most common enterprise malware delivery method. Rendering all documents as flattened PDFs inside isolation neutralises this entire attack category at the container level: users keep their productivity while the threat surface is completely eliminated, with no endpoint ever executing document-borne code.

08
Protecting against Zero Day Threats — Document Isolation + Cloud Sandbox
Sandbox Integration · Quarantine & Isolate · Protected Storage · Verdict · Web Insights
›
OVERVIEW
Browser Isolation integrates with Zscaler Cloud Sandbox. When a potentially malicious document is downloaded, it is immediately rendered as a flattened PDF in isolation while Sandbox analysis runs in parallel. If the verdict is benign, the user can download the original. If malicious, only the flattened PDF is available.
OBJECTIVES
  • Review the Quarantine and Isolate action configured in the Sandbox policy
  • Observe an XLSM file placed in Protected Storage while Sandbox analysis runs in parallel
  • Confirm the file becomes downloadable after a benign verdict and review the full Sandbox report
8.1
Enable Cloud Sandbox + Isolation
›
Review the isolation profile and sandbox policy that enable the Quarantine and Isolate workflow.
  1. Navigate to Administration > Browser Isolation → scroll to the TZTE Download and Copy profile → verify that Isolation to local computer — Sandbox Scanned is enabled
  2. Navigate to Policy > Sandbox → click the icon next to Sandbox Isolation
  3. Review the document file types configured for Quarantine and Isolate on first-time file sightings
    • The Quarantine and Isolate action applies to document file types only
★
NOTE
The Sandbox Scanned option in the Isolation Profile is only visible to accounts with full (not read-only) admin access. As a read-only admin you are reviewing the configured state.
8.2
Test the Configuration
›
  1. On the Client PC VM, navigate to: https://securitytest.zsdemo.com/passwordless/browser-isolation.php
  2. Click the icon in the upper-right corner of the isolation session → click to view Protected Storage
  3. Note the XLSM file in Protected Storage — view it as a flattened PDF while Sandbox analysis runs:
    • Semi-closed circle = Sandbox analysis in progress
    • Green shield = file is safe and available to download
  4. Once the verdict is benign, download the original file to your local computer
  5. Review logs: navigate to Analytics > Web Insights → Logs → add filters for <Marketing Test User> and URL containing securitytest.zsdemo.com → Apply Filters
  6. Click the 3 dots (upper right) → Select All or search for the MD5 field
  7. Click the link in the MD5 column → view the Sandbox Detail Report → scroll through the full analysis
WHY THIS MATTERS

The Quarantine and Isolate workflow solves the zero-hour file problem: at first sight, no file can be conclusively classified. Instead of forcing a binary allow/block decision and stalling the user on a quarantine page, they get immediate safe access to a rendered version while analysis runs in parallel — eliminating both risk and the productivity disruption of waiting for a sandbox verdict.

ZIA enforcement inside BiB also prevents accidental pivot to further malicious infrastructure during an investigation.

ZPA · User Portal 2.0 · M365 · BYOD · IdP Conditional Access · CNAME · Isolation

  2. Verify DNS resolution for the private app: nslookup gitlab.thezerotrustexchange.com Confirm the hostname resolves to the CNAME seen in task 11.1

Developers and contractors who need access to internal tools like Gitlab represent a significant data exfiltration risk — source code and proprietary IP are high-value targets. ZPA Browser Access + isolation eliminates the need for VPN credentials or agents: the private app is fully usable in the browser session, but isolation controls at the data layer ensure code and content cannot be extracted to the contractor's device.
