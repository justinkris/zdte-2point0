Configuring SSL Inspection Policies
⏱ 45 minutes · ZIA · SSL Inspection · Bypass · Certificate Pinning · Web Insights
›
SCENARIO
Enable full SSL/TLS inspection so Zscaler can enforce policies on encrypted traffic. Configure exemptions for privacy-sensitive sites (Healthcare), resolve certificate pinning errors for applications like Signal and Adobe Reader, and verify inspection events in Web Insights logs.
OBJECTIVES
  • Create Forwarding Profile and App Profile for ZCC with Z-Tunnel 2.0
  • Enable SSL Inspection for all destinations
  • Configure SSL exemptions for Healthcare/Financial categories
  • Verify Zscaler CA certificate installation in system and browser stores
  • Resolve certificate pinning errors for Signal and Adobe Reader using SSL bypass rules and custom URL categories
  • View SSL inspection and bypass events in Web Insights Logs
2.1
Configure Forwarding Options
›
Create a Forwarding Profile that intercepts traffic on all network types (trusted, VPN, off-trusted) for both ZIA and ZPA. Then create an App Profile to deploy it.
  1. On Corp: Client PC, open Chrome → login to ZIdentity → select Zscaler Client Connector tile → navigate to Administration > Forwarding Profile
  2. Click Add Forwarding Profile and configure:
    • Name: HandsOnLab
    • Windows Driver Selection: Packet Filter Based
    • ZIA — On-Trusted Network: Tunnel, Tunnel version: Z-Tunnel 2.0
    • Expand Configure System Proxy Settings → select Enforce, all options unchecked
    • VPN Trusted Network: Same as On-Trusted Network
    • Off Trusted Network: Same as On-Trusted Network
    • ZPA — On-Trusted Network: Tunnel; VPN & Off-Trusted: Same as On-Trusted
    • Click Save
  3. Navigate to App Profiles > Windows → click Add Windows Policy:
    • Name: HandsOnLab · Rule Order: 1 · Status: Enable
    • Forwarding Profile: HandsOnLab
    • Install Zscaler SSL Certificate: On
    • User Groups: Select All → Done → Save
  4. Login to Zscaler Client Connector:
    • Click Show hidden icons in the taskbar → Zscaler icon → Open Zscaler
    • Sign in with your student admin credentials
    • Confirm ZIA and ZPA show ON
    • Click More → Update Policy
★
NOTE
Z-Tunnel 2.0 is required to intercept ALL ports/protocols and tunnel them to ZIA for Firewall functionality. Z-Tunnel 1.0 only handles HTTP/HTTPS.
2.2
Enable SSL Inspection for All Destinations

Configure a bypass rule for Healthcare sites to comply with privacy regulations — these sites should not be inspected.
  1. Test first — open https://health.com and check the certificate. It will show Zscaler as the issuer (currently inspected).
  2. In ZIA Portal, navigate to Policy > Web > SSL Inspection → click +Add SSL Inspection Rule:

2.5
Certificate Pinning Errors — Signal, Web Insights & Adobe Reader
›
Certificate pinning causes app failures when Zscaler replaces the server certificate. Resolve pinning errors for Signal (using Cloud App SSL bypass) and Adobe Reader (using a custom URL category), then verify events in Web Insights Logs.

2.5a — Signal Application

  1. Download Signal on Corp: Client PC — search Signal download in browser → Download for Windows
  2. Run the installer from Downloads — you will encounter a connection error due to certificate pinning.
  3. Fix — create an SSL bypass rule for Signal:
    • ZIA Portal → Policy > SSL Inspection → Add SSL Inspection Rule
    • Rule Order: 1 · Rule Name: Enable Signal
    • Cloud Applications → Instant Messaging → select Signal → Done
    • ACTION → Do Not Inspect → Save → Activate
  4. Kill Signal in Task Manager, then re-run the installer from Downloads — it should now install successfully.

2.5b — Web Insights SSL Logs

  1. In ZIA, navigate to Analytics > Web Insights → click the Logs icon → Logs tab
  2. Configure filters:
    • Timeframe: Current Day
    • Add Filter → SSL Inspected and Bypassed Transaction → Apply Filters
  3. Review SSL inspected vs bypassed events. Add the SSL Policy Reason filter column for more detail.
★
NOTE
Allow approximately 5 minutes for logs to appear.

2.5c — Adobe Acrobat Reader

  1. Download Adobe Acrobat Reader on Corp: Client PC — search Adobe Acrobat Reader download → Download → run installer. You will encounter a connection error.
  2. Create a custom URL Category with Adobe's hosted domains:
    • ZIA Portal → Administration > Resources > URL Categories
    • Open the Adobe Product Support page in a separate browser window and copy the list of Adobe hosted domains (without the *)
    • Click Add URL Category
    • Name: Adobe URL List
    • Paste domains into the Custom URL text box → Add Items → Save → Activate
  3. Create an SSL bypass rule for Adobe:
    • Policy > SSL Inspection → Add SSL Inspection Rule
    • Rule Order: 1 · Name: Enable Adobe · Status: Enable
    • URL Categories → Adobe URL List (under User-Defined Category) → Done
    • ACTION → Do Not Inspect → Save → Activate
  4. Kill Adobe Download Manager in Task Manager, then re-run the installer. When prompted: Username Administrator / Password Admin-123!. Installation should succeed.
WHY THIS MATTERS

SSL Inspection is the prerequisite that unlocks every advanced ZIA control — without it, all HTTPS traffic passes as an encrypted black box that Zscaler cannot inspect. Properly configuring bypass rules for certificate-pinned apps (like Adobe) and sensitive categories (healthcare, finance) prevents inspection-related breakage without creating security blind spots.

DNS Security
⏱ 20 minutes · DNS Control Policy · DNS Filtering · DNS Insight Logs
›
SCENARIO
Zscaler DNS Security proxies all DNS requests through the Zero Trust Exchange, allowing policy enforcement at the DNS layer. Configure DNS domain inclusion in the App Profile to route DNS through Zscaler, create a policy to block gambling sites at the DNS level, and verify the block in DNS Insight Logs.
OBJECTIVES
  • Configure App Profile DNS domain inclusion (*) to route all DNS through Zscaler
  • Create a DNS Control policy to block the Gambling category
  • Test DNS blocking from the command line using nslookup
  • Verify blocking events in DNS Insight Logs
3.1
Configure App Profile DNS Settings
›
  1. On Corp: Client PC, login to ZIdentity → select Zscaler Client Connector tile → navigate to App Profile > Windows
  2. Click the edit (pencil) icon on the HandsOnLab policy
  3. Under Traffic Steering, click the DNS tab
  4. Click the Domain Inclusion text box → type * → click Create "*"
  5. Click Save → More → Update Policy
3.2
Configure DNS Control Policy
›
  1. Test DNS before policy — open command prompt: nslookup www.gambling.com 8.8.8.8 The request resolves successfully (no policy yet).
  2. In ZIA Portal, navigate to Policy > Firewall > DNS Control
  3. Click Add DNS Filtering Rule:
    • Rule Order: 1 · Rule Name: Block Gambling · Status: Enabled
    • Click the DNS Application tab
    • Request Categories → drop-down → select Gambling → Done
    • Repeat for Response Categories → Gambling → Done
    • Scroll down → ACTION → select Network Traffic to Block
    • Click Save → Activate
  4. Test DNS after policy: nslookup www.sdxcentral.com 8.8.8.8 This should resolve (not gambling). ipconfig /flushdns nslookup www.gambling.com 8.8.8.8 This should now time out (blocked).
3.3
DNS Insight Logs
›
  1. In ZIA Portal, navigate to Analytics > Insights > DNS Insights > Logs
  2. Configure filters:
    • Timeframe: Current Day
    • Add Filter → Rule Name: Block Gambling
    • Click Apply Filters
  3. Review the blocked DNS request log entries confirming the Block Gambling rule was hit.
WHY THIS MATTERS

DNS is often called the "phone book of the internet" but it is also the most frequently abused protocol in malware infrastructure — C2 callbacks, data exfiltration via DNS tunnelling, and domain generation algorithms all rely on unmonitored DNS traffic. Zscaler's DNS Security layer blocks these at the resolution level, before any IP connection is ever attempted.

Browser Isolation
⏱ 30 minutes · Isolation Profiles · URL Filtering · Cloud App Control · Smart Browser Isolation
›
SCENARIO
Browser Isolation runs risky or suspicious websites in a cloud container — only pixels are transmitted to the user's browser. Configure a Render Only isolation profile (no copy/paste/download/upload), attach it to URL Filtering and Cloud App Control rules for social networking sites, and enable Smart Browser Isolation to automatically isolate AI/ML-detected suspicious URLs.
OBJECTIVES
  • Create a Render Only Isolation Profile
  • Implement a URL Filtering policy that triggers Browser Isolation for Social Networking
  • Configure Cloud App Control with Isolation action for Twitter/Reddit
  • Enable AI/ML-based Smart Browser Isolation and test on a suspicious URL
5.1
Build Isolation Profile
›
  1. In ZIA Portal, navigate to Administration > Browser Isolation → click Add Profile
  2. Configure the profile:
    • Name: Render Only
    • Description: Render docs in Isolation, but not allow download, upload, copy, or paste
    • Click Next
  3. Company Settings — ROOT CERTIFICATES: Zscaler Root Certificate
  4. Security: leave at default
  5. Regions — Isolation Regions: Any
  6. Click Save
5.2
Implement Isolation Policy
›
  1. In ZIA Portal, navigate to Policy > URL & Cloud App Control → URL Filtering Policy tab → Add URL Filtering Rule
  2. Configure the rule:
    • Rule Order: 1 · Rule Name: Isolate Test
    • URL Categories: Social Networking, Social Networking Adult
    • Protocols: HTTP, HTTPS
    • User Agent: Chrome, Firefox, Microsoft Edge, Safari
    • ACTION → Web Traffic: Isolate · Isolation Profile: Render Only
    • Save → Activate
5.3
Add Cloud App Isolate Control Policies
›
  1. In ZIA Portal, navigate to Policy > URL & Cloud App Control → Cloud App Control Policy tab → Add dropdown → Social Networking
  2. Configure the rule:
    • Rule Order: 1 · Rule Name: Social_Networking_2
    • Cloud Applications: Twitter and Reddit
    • User Agent: as shown in the portal
    • ACTION → Web Traffic: Isolate · Isolation Profile: Render Only
    • Save → Activate
  3. Test isolation by going to reddit.com or twitter.com in Chrome — the page should open in the isolated cloud browser.
5.4
Smart Browser Isolation
›
Smart Browser Isolation automatically isolates potentially malicious web content using AI/ML without requiring explicit URL categories.
  1. Test the suspicious URL before enabling Smart Isolation — open Incognito → https://work-nutjobber.store. Note that it loads without isolation.
  2. In ZIA Portal, navigate to Policy > Secure Browsing → Smart Isolate tab → enable AI/ML based Smart Browser Isolation (leave other options as default) → Save → Activate
  3. Open the link again in Incognito — the URL should now be automatically isolated.
WHY THIS MATTERS

Browser Isolation is the last line of defence for web content that cannot be cleanly categorised as safe or malicious — risky but permitted sites, new domains, social media, and unclassified URLs. By rendering content server-side and streaming only pixels, even a fully compromised site cannot deliver malware to the endpoint, regardless of what it contains.

  7. Back in the ZPA Admin Portal on Win Svr 2016, navigate to Configuration & Control > Private Infrastructure > App Connectors and confirm the connector appears. Check the Update Status field.

  5. Click the MD5 value of a malicious file → View Sandbox Detail Report. Review forensic details: registry changes, network connections, files read.
  6. Navigate to Analytics > Web Insights → Logs tab
  7. Click Add Filter → Sandbox → select all Sandbox options → Done → Apply Filters
  8. Scroll through log details. Add/remove columns as needed using the column picker.
WHY THIS MATTERS

Unknown file threats — zero-days, polymorphic malware, newly weaponised document formats — cannot be detected by signature-based controls alone. Inline sandboxing with a Quarantine-then-Block workflow neutralises this category by detonating suspicious files in an isolated cloud environment before they ever reach the endpoint, while the detailed forensic reports accelerate incident response when threats are confirmed.

WHY THIS MATTERS
